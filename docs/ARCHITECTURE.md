## Components

| Component | Responsibility | Code |
|---|---|---|
| Entry points | Thin adapters only: CLI, HTTP API, background worker, Kafka relay | `cli.py`, `api/app.py`, `jobs/worker.py`, `events/relay.py` |
| Composition root | The one place where concrete classes are wired together | `container.py` |
| PipelineRunner | Run lifecycle, advisory lock, stage sequencing, run summary | `pipeline/runner.py` |
| Stages | Bronze → silver → quality gate → gold; shared bookkeeping in a template class | `pipeline/` |
| Agents | Classification, data quality, gold design; they **propose**, never write data | `agents/` |
| Review gate | Proposal store, trust policy, human decisions, per-kind appliers | `agents/proposals.py`, `agents/judge.py` |
| LLM gateway | Guardrails, cache, provider chain, validation and repair, metering | `llm/` |
| Storage | PostgreSQL: `bronze`, `silver`, `gold`, `gold_sandbox`, `ref`, `ops` schemas | `migrations/`, `sql/gold/` |

## Design patterns, where they earn their place

| Pattern | Where | Why |
|---|---|---|
| Template Method | `pipeline/stage.py`, `llm/providers/base.py` | Stage bookkeeping (metrics, lineage events, logs) and SDK error translation are written once. |
| Strategy | keyword / LLM / native-Jev classifiers; per-kind proposal appliers | Same agent, interchangeable "brains"; adding a proposal kind doesn't touch the review gate. |
| Decorator | circuit breaker / retry / rate limit / metering around each provider | Each resilience concern is one small class; adapters only translate protocols. |
| Chain of Responsibility | `LLMRouter` fallback chain | A provider failure, guardrail rejection or invalid output falls through to the next provider. |
| Repository | LLM cache, proposals | In-memory for tests, Postgres in production. |
| Transactional Outbox | `events/outbox.py` + `events/relay.py` | Events exist if and only if the state change committed: no dual write to Kafka. |
| Composition root / DI | `container.py` | Everything else depends on interfaces, not concrete classes. |

## SOLID, concretely

| Principle | How it shows up |
|---|---|
| **S**ingle responsibility | Provider adapters only translate protocols and errors. Retry, rate limiting, circuit breaking and metering are separate decorators. Parsers are pure functions with no I/O. |
| **O**pen/closed | New provider = new adapter registered in the factory. New proposal kind = `@register_applier`. New gold model = new SQL file. No existing code changes in any of those cases. |
| **L**iskov substitution | Every adapter, decorator and the router all satisfy `LLMProvider.complete()`; the eval harness swaps in-memory caches and recorders freely. |
| **I**nterface segregation | Small protocols: `Classifier`, `LLMCache`, `UsageRecorder`, `EventPublisher`, `MessageProducer`. |
| **D**ependency inversion | Agents get a router, the runner gets a `router_factory`, stages get a `RunContext`. Only `container.py` and `llm/factory.py` know concrete classes. |

## Project layout

```
src/medallion/
  settings.py              all configuration from env/.env (pydantic-settings, SecretStr for keys)
  container.py             composition root
  cli.py · api/app.py      entry points (CLI, FastAPI)
  jobs/worker.py           background worker (job queue in ops.pipeline_runs)
  events/                  transactional outbox + Kafka relay
  db.py                    pool, transactions, advisory lock, checksummed migrations
  observability/           trace context (W3C traceparent), JSON logging
  resilience/              retry/backoff/jitter + polling, token bucket, circuit breaker
  llm/                     gateway: types, guardrails, router, cache, decorators, adapters, pricing, factory
  pipeline/                stage template, bronze, tagging, silver/{parsers,transform,stage}, quality, gold, runner
  agents/                  classification, data_quality, gold_design, jev (native), judge (+trust), memory,
                           loop (repair), proposals (review gate), profiler, sql_guard, evaluation,
                           experiments, prompts/*.md (versioned)
config/
  taxonomy.yaml            business-owned categories, assignee master data, junk markers
  ontology.yaml            category overlaps, party qualifications
  seeds/                   human-reviewed agent output (label map, template map, DQ checks)
  memory/                  episodic (episodes.jsonl) and procedural (procedures/*.md) agent memory
migrations/                ordered, checksummed SQL migrations
sql/gold/                  gold models + knowledge graph (plain SQL)
evals/                     labelled datasets + saved A/B results (results/reference/)
docs/                      this documentation + diagrams
tests/unit · tests/integration
```
